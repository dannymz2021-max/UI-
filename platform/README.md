# UI工作室 · AI创作台

原「Icon生成工作台」和「AI图像生成」已合并为一个AI创作台，图片与Icon共用自然语言创作流程。旧的 `#icons` 和 `#image` 地址会进入 `#creator`。

## 工作流程

描述需求 → 可选参考图 → 需求清单 → 真实模型调用 → 自然语言修改 → 历史版本 → PNG下载或继续拆层。

## 按需求生成 Megwin 页面

打开 `/studio/#ui` →「需求生成」。粘贴需求或导入 TXT / Markdown PRD；可选参考图片。可以用「页面类型：」「主题：」「区块：」「去掉：」「标题：」「副标题：」「按钮：」逐行指定，区块列表的顺序用于排列主体内容。顶部导航、侧栏和原稿右栏保留各自的位置。

- 本地方式无需模型或 Figma 登录，可从两个已归档原稿组合区块，并复用其颜色、圆角、文字样式和原始素材。浅色变量不会改写内嵌插画。活动页基于已归档快照；来源清单同时提供现版 Figma 活动区入口。
- 「用 AI 解读」可选，使用同一 OpenAI 服务解析长需求或参考图。只允许返回原稿区块、变量模式和有限文案，渲染器不会执行模型生成的代码。本地方式只展示参考图供对照。
- 预览可导出含图片和字体的桌面 HTML，另可下载带原稿文件、节点、区块和核对项的来源清单。手机适配、真实业务交互、任意新组件和可编辑 Figma 文件不在当前范围内。

## 运行

需要 Node.js 22.13+ 和 pnpm 11.25.0。首次运行：

```sh
pnpm install
pnpm run build
```

按 Sites 模板说明，将 `drizzle/` 中尚未应用的SQL迁移依次应用到本地D1，再运行：

```sh
pnpm run dev
```

打开终端打印的本地地址 `/studio/#creator`。本地登录使用模板提供的测试身份。生产环境沿用 Sites 登录及现有私有访问权限。

## 豆包与模型配置

生产环境改用 `AI_PROVIDER=ark`：

- `ARK_API_KEY`：火山方舟专用密钥，保存为站点后端 secret。
- `ARK_TEXT_MODEL=doubao-seed-2-1-pro-260915`：需求、参考图、PRD 的识别和严格 JSON 规划。
- `ARK_IMAGE_MODEL=doubao-seedream-5-0-pro-260628`：生图与自然语言图片编辑。
- 仅使用火山方舟标准 API；Agent Plan 的专属密钥和接口不能直接套用。

选择豆包后，全部新模型请求仅调用火山方舟。保留的 OpenAI 配置用于明确切换回 `AI_PROVIDER=openai` 时使用，不会自动回退并产生其他服务商的费用。

透明图采用两种流程：已有透明基图且无额外参考时，执行透明编辑；新透明图或多图参考时，先生成，再调用 Seedream 图层拆分提取完整前景，按官方边界框和 z 顺序将全部前景层自动合并回原画布，使用 Alpha 叠加保留半透明边缘。若文件或图层缺失、顺序重复、坐标不符或无有效 Alpha，会停止交付并说明原因。此路径会产生额外用量；模型语义与边缘保真仍需对照原需求验收。

## OpenAI 兼容配置

- 文本需求理解：`OPENAI_TEXT_MODEL`，默认 `gpt-6-astra`。
- 图像生成和编辑：`OPENAI_IMAGE_MODEL`，默认固定为 `gpt-image-2.5-sunburst-2026-09-08`。
- 服务端凭据：`OPENAI_API_KEY`。
- 过去24小时的生成次数上限：`AI_DAILY_LIMIT`，默认10；每个账号同时只允许一项未确认任务。
- D1绑定：`DB`；R2绑定：`BUCKET`。

本地密钥通过批准的安全配置流程写入 `.env.local`。该文件和密钥准备目录均已忽略，不能提交或加入源码包。线上密钥应通过 Sites 的安全环境变量配置功能设置；仓库只记录变量名称。

## 已实现的保护和证据

- 原始文字保留；需求按主体、数量、颜色、材质、构图、文字、禁止项和保留项整理。
- 最多三张参考图，可指定仅参考主体、风格、材质、颜色或构图。整理后修改文字、参考用途或基图，必须重新整理。
- 只对缺失的关键条件提出澄清；不支持的输出尺寸会说明原因，不偷偷缩放或拉伸。
- 修改携带指定基图和上一版需求，保留父版本。模型编辑仍可能改变其他细节，不承诺像素级完全不变。
- PNG进行解码、尺寸、非空像素与真实Alpha检查。内容和文字的正确性仍需要对照需求清单核验。
- 服务端任务ID防重复计费；网络错误先恢复原任务，不自动重发生成。超时不能被当成已取消。
- API密钥错误、余额不足、模型权限、限流、输入错误和文件检查失败分别处理。
- 图片文件通过登录身份鉴权，D1/R2记录与文件按用户隔离。
- 需求、参考和版本存于当前浏览器；服务端保留任务状态与结果用于恢复。旧域名浏览器数据不自动迁移。

## 验证

```sh
node scripts/check.mjs
node --test tests/creator.test.mjs tests/ui-compose.test.mjs tests/ark.test.mjs
node --env-file=.env.local --env-file=.env.ark.local scripts/check-secrets.mjs
```

静态资源、脚本语法和13项接口/文件测试已通过。接口测试使用模拟模型响应验证状态与计费防重，不能证明模型实际画面质量。浏览器已验证统一入口、参考图上传、参考用途选择、刷新恢复、服务错误提示与布局。

`scripts/verify-openai.mjs` 可读取本地环境安全验证真实模型；不会输出密钥。默认只整理一次测试需求，显式追加 `--generate` 才会执行图像生成。额度错误不得自动重试。

源码位置：`public/studio/` 为创作界面；`public/splitter/` 为拆层；`server/` 为模型请求与PNG校验；`db/`、`drizzle/` 为任务及服务状态；`worker/` 为服务入口。

真实验收脚本默认不调用模型。经明确同意测试费用后，可使用 `node --env-file=.env.ark.local scripts/verify-ark.mjs --allow-paid-test` 验证一次需求理解；追加 `--generate` 验证 Flash 预览；只有再加 `--final --allow-paid-extraction` 才允许正式透明图的额外拆层；`--edit` 另外验证一次修改。产物保存在忽略的 `.sites-runtime/ark-verification/`，密钥不会打印到输出。

若普通生图已返回但后续提取失败，可追加 `--resume-image .sites-runtime/ark-verification/<原图文件>.png` 复用已保存的真实原图，只重新验证提取和修改。脚本会明确标记缓存复用并记录原图摘要；不把缓存步骤说成新的模型调用。
