# UI工作室 · AI创作台

原「Icon生成工作台」和「AI图像生成」已合并为一个AI创作台，图片与Icon共用自然语言创作流程。旧的 `#icons` 和 `#image` 地址会进入 `#creator`。

## 工作流程

描述需求 → 可选参考图 → 需求清单 → 真实模型调用 → 自然语言修改 → 历史版本 → PNG下载或继续拆层。

取消了主流程中的手工建模、主体拼装及材质/镜头/灯光滑杆。主站、活动、拆层、组件快照与原作品库继续保留。素材库中的旧图标明确标为历史参考，不会冒充AI生成结果。

## 运行

需要 Node.js 22.13+ 和 pnpm 11.25.0。首次运行：

```sh
pnpm install
pnpm run build
```

按 Sites 模板说明，将 `drizzle/` 中尚未应用的SQL迁移依次应用到本地D1，再运行：

```sh
pnpm run dev
```

打开终端打印的本地地址 `/studio/#creator`。本地登录使用模板提供的测试身份。生产环境沿用 Sites 登录及现有私有访问权限。

## 模型与安全配置

- 文本需求理解：`OPENAI_TEXT_MODEL`，默认 `gpt-6-astra`。
- 图像生成和编辑：`OPENAI_IMAGE_MODEL`，默认固定为 `gpt-image-2.5-sunburst-2026-09-08`。
- 服务端凭据：`OPENAI_API_KEY`。
- 过去24小时的生成次数上限：`AI_DAILY_LIMIT`，默认10；每个账号同时只允许一项未确认任务。
- D1绑定：`DB`；R2绑定：`BUCKET`。

本地密钥通过批准的安全配置流程写入 `.env.local`。该文件和密钥准备目录均已忽略，不能提交或加入源码包。线上密钥应通过 Sites 的安全环境变量配置功能设置；仓库只记录变量名称。

## 验收边界

代码、静态资源和接口状态测试已通过。模拟响应只能验证接口与文件处理，不能证明真实模型的画面质量。使用前需要配置服务端模型凭据和可用API额度，并完成真实生成、参考图生成和连续修改验收。

## 已实现的保护和证据

- 原始文字保留；需求按主体、数量、颜色、材质、构图、文字、禁止项和保留项整理。
- 最多三张参考图，可指定仅参考主体、风格、材质、颜色或构图。整理后修改文字、参考用途或基图，必须重新整理。
- 只对缺失的关键条件提出澄清；不支持的输出尺寸会说明原因，不偷偷缩放或拉伸。
- 修改携带指定基图和上一版需求，保留父版本。模型编辑仍可能改变其他细节，不承诺像素级完全不变。
- PNG进行解码、尺寸、非空像素与真实Alpha检查。内容和文字的正确性仍需要对照需求清单核验。
- 服务端任务ID防重复计费；网络错误先恢复原任务，不自动重发生成。超时不能被当成已取消。
- API密钥错误、余额不足、模型权限、限流、输入错误和文件检查失败分别处理。
- 图片文件通过登录身份鉴权，D1/R2记录与文件按用户隔离。
- 需求、参考和版本存于当前浏览器；服务端保留任务状态与结果用于恢复。旧域名浏览器数据不自动迁移。

## 验证

```sh
node scripts/check.mjs
node --test tests/creator.test.mjs
node --env-file=.env.local scripts/check-secrets.mjs
```

静态资源、脚本语法和13项接口/文件测试已通过。接口测试使用模拟模型响应验证状态与计费防重，不能证明模型实际画面质量。浏览器已验证统一入口、参考图上传、参考用途选择、刷新恢复、服务错误提示与布局。

`scripts/verify-openai.mjs` 可读取本地环境安全验证真实模型；不会输出密钥。默认只整理一次测试需求，显式追加 `--generate` 才会执行图像生成。额度错误不得自动重试。

源码位置：`public/studio/` 为创作界面；`public/splitter/` 为拆层；`server/` 为模型请求与PNG校验；`db/`、`drizzle/` 为任务及服务状态；`worker/` 为服务入口。
